# StoreBot progress

## Part 1: Foundation (done)
- prisma/schema.prisma: CORE block (Guild, MessageOverride, Panel, BotJob, AuditLog, IdempotencyKey). Modules append their models below it.
- bot/core: env self-check, config cache + 5s version polling, jobs poller (atomic claim), module loader, button/select/modal router (custom_id `<module>:<action>:<id>[:<extra>]`), guard (cooldown, isStaff, claim for idempotency), i18n with DB overrides, /health.
- bot/modules/general: sample module (welcome panel, ping button, publishPanel job, guildCreate event). Module contract: index.js {name, defaultEnabled, panels}, buttons.js {action: fn}, events.js {eventName: fn}, jobs.js {jobName: fn}. Job type = `<module>:<jobName>`.
- Deploy: ecosystem.config.js (PM2), Dockerfile, docker-compose.yml (restart: always), .env.example.
- dashboard: Next.js 14 + NextAuth (Discord), RTL layout, sidebar auto-built from dashboard/modules/*.ts, guildRoute() wrapper (session + Manage Server + zod + errors), messages editor (bumps config_version), panel publish button (enqueues a bot job). `npm run sync` copies ar.js and schema into dashboard/.

## Not yet built / known gaps
- Dashboard-role permissions (only Manage Server/Admin today) and a settings page for staffRoleIds and per-guild module toggles (API + UI).
- Channel picker (publish form takes a raw channel ID; needs a bot-synced channel list table).
- Per-module dashboard pages, audit log viewer, premium gating UI (helper `allowFeature` exists, not enforced).
- AI quota helper (Groq/Gemini), sharding manager entry (flag only), rate-limit middleware for API routes.
- Store, Tickets, Protection, Staff tools, Analytics modules.
- Not run against a live Supabase DB or Discord yet; only syntax-checked.

Data contracts for Step 3 (assumptions):

- Package.priceOverrides[methodId] = amount in THAT method's own currency (EGP for vodafone, credits for credit methods) BEFORE fee/tax.

- Manual status change in dashboard only updates DB + audit log + orders log; role/key reversal and ticket embed refresh arrive with Step 3 (`store:orderStatusChanged` job).

Libs: days (local-day boundaries, DST/half-hour safe), tracker (in-memory counters flushed every 60 s; message TEXT is never stored), aggregate (nightly day -> AnalyticsDaily + 14-day health snapshot), health (healthScore + bestTimes, pure), retention (churn list + subscriptions), digest (collect/embed/post), summaries (optional AI), settings.
Nightly job: at the first 5-minute tick after local midnight (claim key `insights-agg:<guild>:<day>`, so restarts never duplicate) aggregates the previous local day: members joined/left (live-incremented), messages by hour/channel, active members (distinct per day), orders opened/paid, revenue by product and by method, tickets opened/closed, shield incidents, health score.
Weekly Digest (default Saturday 10:00 guild time; embed in a private channel = settings.digestChannelId or staff log channel, + optional owner DM): member growth with week-over-week deltas, leavers, peak weekday/hours (28-day heatmap), top channels, revenue (total, best product, average order value, order->paid conversion), ticket stats, shield incidents, health score + 3 tips, churn count, expiring/lapsed subscriptions. Stored in InsightsDigest (idempotent per week).
Churn alert: members with >=3 active days in the last 30 and silent for N days (default 7, settings.churnDays; still in the guild) -> dashboard list + weekly digest count. Subscriptions expiring within 3 days or lapsed within 30 days -> dashboard list with one-click «إرسال تذكير تجديد».
Best time to post: 7x24 heatmap (guild timezone) + top 3 slots. Server Health Score 0-100: activity 30 + growth/retention 25 + support 20 (if ticket categories exist) + safety 15 + store 10 (if products exist), renormalised; shows per-part explanation and the 3 weakest-area tips.
Optional daily Arabic AI summary: per toggled channel, hard cap per day (settings.aiSummary.cap, max 10) and the shared per-guild AI quota; silently skipped when the AI is disabled/exhausted; a sample of up to 150 recent messages per channel is kept IN MEMORY only (links stripped, no author names) until summarised; summaries saved in AiSummary and posted to a chosen channel.
Dashboard `/[guildId]/insights` tabs: analytics (range 7-90 days, 9 KPI cards, Recharts: growth, messages/active, messages by hour, top channels, revenue/orders, revenue by product and method, recent AI summaries), retention (churn + subscriptions), best time (heatmap), health (gauge, explanation, tips, send digest now / re-aggregate yesterday), settings. API: insights/{overview,heatmap,retention,settings}. Settings JSON: Guild.settings.insights.
Tests: bot/test/insights.test.js (local-day ranges incl. Cairo DST + half-hour zones, health scoring, best times). 53 passing total (`cd bot && npm test`).
Limitations: charts start empty until the first nightly aggregation (history is not back-filled; counting starts when the bot first sees messages); the churn query in dashboard/api/.../retention mirrors bot/lib/retention.js — keep in sync; active-member/churn data needs the MessageContent-free message events only (no content stored); not run against live Discord.
